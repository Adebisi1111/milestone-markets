The problem

A market on “did this ship on time” can’t be settled by a price feed.

The answer lives in code — merge dates, whether the tests actually exist, whether the file the milestone named is really in the tree. Settling it means reading and judging unstructured evidence. That is the whole difficulty, and it is why most such markets quietly fall back to a human deciding.

How it works

Four steps, no human in the loop.

Every step below is a real transaction on the deployed contract.

1

Open a market

createMarket(repo, criteria, deadline) — that is the entire input. There is no field for an evidence URL, so no creator can choose what gets read.

2

Stake YES or NO

GEN goes into a parimutuel pool. Staking closes the moment the deadline passes, and the odds preview on the app updates as you type.

3

The validators judge

After the deadline, every validator independently fetches the repository and runs the same evaluator prompt. Comparative consensus reconciles their verdicts.

4

Winners get paid

The pool is split in proportion to each winner's stake and paid in native GEN. If the winning side drew no stake, the market voids and everyone is refunded instead.

The evaluator prompt — sent to every validator, verbatim 
# the repository digest is built by the contract, not supplied by the caller
You are an expert software engineer acting as an autonomous GenLayer validator.
Your task is to objectively determine if an open-source development milestone
has been successfully achieved.

### DATA SOURCED FROM GITHUB:
<commits · merged pull requests · file tree>
MILESTONE DEADLINE (UTC): <iso>

### SUCCESS CRITERIA TO EVALUATE:
"<criteria>"

### RULES FOR EVALUATION:
1. Base your evaluation strictly on the provided GitHub data. Do not hallucinate.
2. The code must be explicitly merged or completed within the repository text.
3. If the criteria mentions specific requirements (tests, files, features),
   verify they actually exist. Empty files or uncompleted PRs count as a failure.
4. The milestone must have been completed ON OR BEFORE the deadline. A merge
   dated after the deadline is late and counts as NO.

### OUTPUT FORMAT:
Reply in valid JSON with exactly two keys: "outcome" and "reasoning".
The "outcome" value must be strictly either "YES" or "NO".
